// how I work

Every system is a feedback loop

I trained as a mechatronics engineer. A controller that acts without checking its own result is unfinished, and I hold software to the same rule.

01

Measure

Start from what the system actually reports: logs, alerts, API responses.

02

Decide

Rules where the answer is known. A language model only where judgment helps.

03

Act

Actions run in deterministic code, so every one can be explained afterwards.

04

Check

Confirm the action worked, and feed the result into the next decision.

Security automation platform for multiple clients

Designed and ledPrivate

ProblemEach client's security team was drowning in alerts, and every client has its own tools, rules and network. One automation platform had to serve all of them without letting one environment reach into another.

My roleI designed the architecture and lead the team that builds and runs it, together with a co-lead. This is the largest system I own, and these are the design decisions I made in it.

Central control, isolated clients
A central instance sends work out to each client's instance. Client instances hold no credentials back into central; central collects their results on a schedule. A compromised client environment cannot be used to reach the others.
Organised by alert family
Email threats, endpoint alerts and authentication alerts each have their own shared enrichment and response logic. A new client reuses a family instead of getting a one-off build, and each engineer on the team owns a family.
Least privilege by design
The automation's identity is scoped to only the users and mailboxes it is allowed to touch. It contains an account by disabling it and revoking sessions, so no password ever passes through the automation or its logs.
Analysts can change it without developers
Investigation queries live in a per-client library the SOC edits directly, so tuning a search does not need a code change or a release.
The model advises, code acts
AI investigation sits on top as an advisor that drafts findings and recommends a response. Every action that changes something is carried out by deterministic, auditable logic.
A team that grew with it
I hired and mentored the interns who built on this platform, and they are now joining as full-time engineers who each own part of it.
